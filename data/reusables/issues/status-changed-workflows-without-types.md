Workflows that use the `issues` event without `types` also run for `status_changed`. These workflows run whenever the status of an issue changes, including automatic changes. They also run an extra time when an issue is created, closed, or reopened, and when assigning an issue changes its status, because {% data variables.product.github %} sends `status_changed` as well as `opened`, `closed`, `reopened`, or `assigned`. To avoid unexpected runs, list the activity types that your workflow needs.
